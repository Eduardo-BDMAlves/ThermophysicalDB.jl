Exporting points ​

export_points writes the points of a selection as a directory of tables that other programs can read. The first argument is the name of the directory, which is created if it does not exist, and formats, a tuple of symbols, chooses the files. The same selection becomes a spreadsheet, a table for a statistics package, a Markdown or LaTeX table for a text, or a file for another Julia session.

julia
using ThermophysicalDB

db = database()
v = points(db; component = "water", exact = true, property = "Mass density")

export_points("data/water", v)                          # the default formats
export_points("data/water", v; formats = (:csv, :md))   # only these
export_points("data/water", v; formats = :thermoml)     # the JSON form of ThermoML
export_points("data/water", v; formats = :thermoml_xml) # ThermoML XML, one file per article
FormatFile written
:csvwater.csv, one table; the unit of every column is in its header
:mdwater.md, the same table as a Markdown (GitHub) table
:texwater.tex, the same table as a LaTeX longtable, ready to include in a text
:jsonwater.json, one record per point
:jld2water.jld2, the columns, the units and the references as Julia data
:xlsxwater.xlsx, one sheet per system, a references sheet and an origin sheet; written when XLSX.jl is loaded
:thermomlwater.thermoml.json, the JSON form of ThermoML (the structure of the archive's JSON files), for the selected points only
:thermoml_xmlthe directory water.thermoml/, one ThermoML XML document per article (named by DOI), valid against the ThermoML schema

The default is (:csv, :md, :tex, :json, :jld2), and :xlsx joins it when the XLSX package is loaded (using XLSX). A DataView or the whole Dataset can be given. A format that is not in the table is an error, so a typo never silently writes something else.

The path is a directory, not a file

The extension of the path does not choose the format any more. export_points("data/water.csv", v) is an error that tells you so, since it is most likely a mistake; use export_points("data/water", v; formats = :csv). A directory whose name has a dot (data/run.v2) is written with a trailing slash: "data/run.v2/".

What a table contains ​

The tables hold points and nothing else. Each row is one measured value with the conditions it was measured at; what describes the article lives in the references table. The two are linked by the reference column, and you choose how it reads:

reference =The cell holdsExample
:key (default)the BibTeX key, the same as in bibtexchirico2003thermoml
:textthe citation written outChirico et al. (2003)
:doithe DOI10.1016/S0021-9614(02)00306-7

The columns follow table, with reference in place of source, doi and year. Each header carries its unit in square brackets:

text
reference,components,xkind,property,temperature [K],pressure [kPa],x1 [-],value [kg/m3],unc [kg/m3],unc_level [-],unc_k2 [kg/m3]
moe1990density,water,Mole fraction,Mass density,293.15,101.325,1.0,998.0,0.1,0.95,0.1020…

  • When the selection mixes properties, the value columns read value [see unit] and a unit column says which unit each row has.

  • The composition columns x1, x2 and x3 carry the unit of the composition they express (- for fractions, mol/kg for a molality); xkind says which one it is, and if the selection mixes kinds the header reads x1 [see xkind].

  • What the references table already tells, and what is the same in every row, is not repeated. The method and the phase of each point are not written (the references table gives them per article); components is left out when the selection has one system, and property when it has one property. A selection with several systems or properties keeps those columns, since the rows could not be read without them. details = true writes all four, which is useful when a file is processed on its own, for instance to filter by phase in a spreadsheet.

  • A column that is empty for the whole selection is left out too (a pure fluid has x1 but no x2), and an empty cell is a missing value: nothing in a .csv or .xlsx, no member in a .json record.

  • units = :si converts values, uncertainties and the pressure to SI, as in table. unc is the uncertainty as the article reported it and unc_k2 is restated at   according to policy.

  • report says how the numbers are written. The default, :source, writes them as the ThermoML standard keeps them: values and uncertainties as stored, with the digits of the source. report = :gum reports a result as a laboratory does (GUM 7.2.6): an uncertainty has at most two significant digits (two when its leading digit is 1 or 2, otherwise one; 6.115e-5 is written 6.0e-5, 0.0187 is written 0.019), and the value is rounded to the last digit of the uncertainty at  , or of the reported one when that is not known. Digits are only taken away, never added; a point without an uncertainty is not changed. In both cases the tables are free of the noise in the last digits that a conversion leaves (see The digits of a number), and the ThermoML formats never round.

The references table ​

A .csv, .md or .tex has no room for a second table, so with references = true (the default) the references are written next to each of them: water_references.csv, water_references.md and water_references.tex, with one row per article and property as in reference_summary, and water.bib. The keys in the reference column are the keys of that file. The other formats carry the references themselves: the references sheet of an .xlsx, the references entry of a .json and the references group of a .jld2. Pass references = false to write the points only.

references = false with reference = :key

A .csv, .md or .tex then holds BibTeX keys and nothing to resolve them with, and the DOI of each article, which credits its authors, cannot be recovered from the files. export_points warns you. Keep references = true, or write the DOI (reference = :doi) or the citation (reference = :text) into the table. The .xlsx, .json and .jld2 hold their references table inside the file and do not need the warning.

The BibTeX entries are fetched from the DOI resolver the first time, as in bibtex, and cached; online = false uses only the cache and the archive, so the export works offline. online, cache, refresh and progress act as there.

Citing the package ​

The .bib ends the credits with the entry of this package, so a paper that uses the export cites the software as well as the data: a comment asks you to cite it, and the entry follows. It is built from the CITATION.cff of the installed version, so it carries that version and, once the release has a DOI (Zenodo) or the file names an article of the package as its preferred-citation, the DOI and the article as a second entry, with no change on your side. No table mentions the package: it appears in the .bib only. include_package = false leaves it out.

The files of a directory ​

julia
export_points("data/Fluid", v)
# data/Fluid/Fluid.csv
# data/Fluid/Fluid.md
# data/Fluid/Fluid.tex
# data/Fluid/Fluid.json
# data/Fluid/Fluid.jld2
# data/Fluid/Fluid_references.csv
# data/Fluid/Fluid_references.md
# data/Fluid/Fluid_references.tex
# data/Fluid/Fluid.bib

All the files are built from the same selection and the same bibliography, so they agree: the same columns, the same units, the same keys. The references table is written in each table format that was chosen (.csv, .md, .tex), and the .bib always. Asking for :xlsx without loading XLSX.jl is an error that says what to load.

The returned ThermophysicalDB.ExportReport lists the files written and the number of points and articles. Nothing is written for an empty selection.

Markdown ​

name.md is the points table in the format of GitHub, Quarto, Jupyter and Documenter: header, an alignment line (text columns to the left, numbers to the right) and one row per point, with the same columns and units as the .csv. A pipe inside a text is escaped. With reference = :key the reference column holds the BibTeX key, and name_references.md is the table of the articles, as markdown_table writes it. The notice is an HTML comment at the top, invisible when the page is rendered.

LaTeX ​

name.tex is the points table as a longtable with booktabs rules (load longtable and booktabs), with the same columns and headers as the .csv. With reference = :key the reference column holds \\cite{chirico2003thermoml}, which resolves against the name.bib written with it; reference = :text writes the citation out instead. name_references.tex is the table of the articles, one row per article and property with the ranges of temperature and pressure and the uncertainty, as latex_table writes it, citing the same keys.

A worked example, with the output of every step, is the tutorial Tables for a paper.

Exporting therefore gives, in one call, the raw points in several formats, the summary of what each article covers, and the bibliography: the data to process and the tables and references to include in a text.

Where the data come from ​

When some of the points come from the ThermoML Archive, every file carries one notice, the same in all formats because the package writes it from a single place. It gives

  • the origin: the archive, its address, the DOI of the dataset and the version of the archive on this computer;

  • the full citation of the dataset (version 1.2);

  • that the data are modified (reformatted, possibly converted to other units) and were not evaluated or endorsed by NIST/TRC;

  • a reminder to credit the original article of each point, by its DOI, and the archive;

  • the address of the terms of use;

  • who exported the file and when.

See About the data for what to cite. Points that come from elsewhere, such as your own data, carry no notice. The notice sits where each format can hold it without disturbing the table:

FormatWhere
.csvthe first line, starting with #, before the headers
.texthe first line, a % comment
.mdan HTML comment (<!-- ... -->) before the table
.xlsxa separate sheet called origin
.jsonthe first entry of the top-level object, origin
.jld2the origin group
name.bib, name_references.csv, name_references.texsee Exporting the references

To read a .csv skip that line:

julia
using CSV, DataFrames
df = CSV.read("data/water/water.csv", DataFrame; comment = "#")

Excel ​

Writing .xlsx files uses XLSX.jl, which is loaded on demand: install it once and load it before exporting.

julia
using XLSX
export_points("data/water", v)                          # the workbook comes with the others
export_points("data/water", v; formats = :xlsx)         # or alone

By default each system gets its own sheet, named after its components and shortened to the 31 characters Excel allows (water, carbon dioxide + methane); a sheet holds up to 1,048,575 points. sheets = :single puts all the points in one sheet called points. Within a sheet, columns that are empty for that system are left out, so a pure fluid has no x2.

JSON ​

The default .json has one record per point, so each point can be read on its own:

json
{
  "origin": { "data_origin": "NIST/TRC ThermoML Archive", "...": "..." },
  "metadata": { "format": "ThermophysicalDB points", "version": 1, "points": 2, "...": "..." },
  "units": { "temperature": "K", "pressure": "kPa", "value": "kg/m3", "...": "..." },
  "points": [
    {"reference": "moe1990density", "components": "water", "property": "Mass density", "temperature": 293.15, "pressure": 101.325, "x": [1.0], "value": 998.0, "unit": "kg/m3", "unc": 0.1, "unc_k2": 0.102},
    {"...": "..."}
  ],
  "references": { "temperature_unit": "K", "pressure_unit": "MPa", "rows": [ {"key": "moe1990density", "...": "..."} ] }
}

The composition of a point is the array x, with one entry per component in the order of components. Values that are not finite are not written.

A point that has uncertainty terms of its own (data you supplied with set_uncertainty!, see Uncertainty) also has the member uncertainties: one record per term, with its quantity, kind, origin (given or derived), value, coverage factor k, level and method; the terms shared by the experiment come first and carry "shared": true. The values are in the units of the file, so with units = :si the pressure terms are in pascal. The data of the archive have no such terms. The ThermoML formats keep only the expanded uncertainty of the property, as the standard has it.

In the ThermoML format ​

formats = :thermoml and formats = :thermoml_xml write the selected points in the structure of the ThermoML standard: one DataReport per article, with its Citation, its Compounds (with their Samples and purity steps) and the PureOrMixtureData that hold only the selected points. The first writes one JSON file with all the articles, the second a directory with one XML document per article, named by its DOI. Units are those of the archive whatever units says. Both need neither the references nor the network.

julia
export_points("data/water", v; formats = (:thermoml, :thermoml_xml))
# data/water/water.thermoml.json and data/water/water.thermoml/<doi>.xml

The elements follow the order that the schema (xsd:sequence) demands, and the XML was checked with xmllint --schema ThermoML.xsd on the whole archive. Compounds are numbered within each article, and every point is one row of NumValues. A few things are derived because the standard requires them and the archive does not always say:

  • The number of significant digits of a value is kept when the archive gives it (temperature, pressure and compositions); otherwise it is counted from the number.

  • A property without a method is written with the method method not stated. The uncertainty of each point is always written; the evaluation of the property (method, level of confidence, coverage factor) only when the method is known, and a warning counts the properties for which a level or a factor was left out.

  • Properties whose name the archive writes with a presentation (a ratio or a difference to a reference state) keep the exact presentation. A composition without a known kind cannot be typed and is not written.

  • The constraints of an experiment and the conditions that are not temperature, pressure or composition (frequency, the composition of a solvent, ...) are kept in the condition table and written as Constraints or Variables with their type, number of digits and phase. The phase of a variable, of a property and of its reference state is written with the compound it refers to (the standard allows one per element), and the solvent of a property as its RegNum. The constraints on temperature, pressure and composition are kept as the source stated them (with their digits and phase) and written back as Constraint; what a constraint fixes is not repeated as a variable of every point.

  • The phase of a property is written as a name of ThermoML, which has a closed list (thermoml_phases). The package keeps the phase as the text you gave, and the export translates a state on the saturation curve, which ThermoML has no word for (see below). A phase with no equivalent is refused, with the closest names.

  • The TRCRefID of an article is written only when its four parts (year, first author, second author and the others) are known, because the schema requires all of them.

  • ReactionData (3% of the articles) is not supported: the package is about properties of substances and mixtures, not of reactions (the heat of combustion of a substance is a pure-compound property and is supported).

Phases and saturation ​

Data at saturation have no pressure of their own: for a pure compound with two phases in equilibrium only the temperature is free (    ), and the pressure is the saturation pressure ; for a mixture, the temperature and the composition fix the bubble or the dew pressure. The archive says so with the phases that coexist in the block of data (PhaseID: Liquid and Gas), the phase the value belongs to (PropPhaseID) and a missing pressure. A point without a pressure can otherwise be at atmospheric pressure and not reported, and the two are different states for a model, so the phase of your own points says which one it is:

You writePhase of the propertyPhases of the block of data
Liquid (saturated)LiquidLiquid, Gas
Vapor (saturated)GasGas, Liquid
Liquid + Vapor (saturated) (a property of the two phases)LiquidLiquid, Gas
VaporGasGas

Case and spaces do not matter, Vapour and Gas mean Vapor, and (saturated) may be left out after a +. Any other text must be one of thermoml_phases (any case); thermoml_phase shows what a text becomes. The text you wrote is kept in the file as sPhaseDescription, next to the ThermoML phase, so whoever reads it sees that the point is at saturation.

julia
using ThermophysicalDB
thermoml_phase("liquid + vapor (saturated)")
PhaseMeaning("Liquid", system = ["Liquid", "Gas"], saturated, description = "liquid + vapor (saturated)")

The ThermoML formats refuse a phase that has no equivalent, before anything is written, and say how many points have it and which names are the closest:

text
ArgumentError: the ThermoML formats need the phase of a point to have a ThermoML name; these have none:
  "Liquido" (12 points): the closest phases of ThermoML are "Liquid", "Liquid mixture 1", "Liquid (saturated)"

update_points! changes the phase of points that are already in a database of yours (update_points!(db, sel; phase = "Liquid (saturated)")), and the template of Excel accepts a phase of your own with a menu that has these names. The other formats keep your text as it is.

Saturation in the archive

The archive has no marker of its own: the saturation of its points is in the property (Vapor or sublimation pressure, Molar heat capacity at saturation pressure, Boiling temperature at pressure P), written for the liquid or the crystal with Gas as the other phase of the block.

Enumerations newer than the schema

The archive uses some values (Metastable liquid, Static method, ...) that are newer than the schema copy in the standard; 20 of 2369 articles sampled fail validation in the archive itself, and the export keeps their text.

Julia ​

A .jld2 holds each column of the table as points/<name>, the units as units/<name>, the headers as metadata/headers, the references as references/<column> and the origin note as origin/<entry>. Values are plain numbers; the units are text.

julia
using JLD2
jldopen("data/water/water.jld2") do file
    T = file["points/temperature"]
    ρ = file["points/value"]
    file["units/value"]       # "kg/m3"
end

Choosing a format ​

If you want toUse
open the data in a spreadsheet, with one sheet per system.xlsx
load them in R, Python, Julia or Matlab.csv (a plain table) or .json
keep every number exactly and reload it quickly in Julia.jld2
hand the data to something that reads ThermoML.thermoml.json or .thermoml/ (XML)
paste the table in a README, a Quarto or a Jupyter text.md
give a colleague everythingthe default directory

Numbers are written with the shortest text that reads back exactly the same Float64, in .csv and .json as well.
