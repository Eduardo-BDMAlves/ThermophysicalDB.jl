Tables, units and Unitful ​

A selection becomes data you can compute with in two steps: table turns it into columns, and the unit options decide how those columns express the numbers.

julia
using ThermophysicalDB, Unitful, DataFrames

db = database(progress = false)
v = points(db; component = "water", exact = true, property = "Vapor or sublimation pressure",
           temperature = (20u"°C", 30u"°C"))

Columns ​

table(v) returns a NamedTuple whose fields are plain vectors of equal length: one row per point.

julia
t = table(v)
keys(t)
(:source, :doi, :year, :components, :xkind, :property, :method, :phase, :temperature, :pressure, :x1, :x2, :x3, :value, :unit, :unc, :unc_k, :unc_level, :unc_k2)
ColumnTypeMeaning
source, doiStringdatabase and article the point comes from
yearInt16publication year
components, xkindStringthe system, as "a + b", and the kind of composition ("Mole fraction", "Molality, mol/kg", …)
property, method, phaseStringwhat was measured, the experimental method and the phase
temperature, pressureFloat64state conditions, in K and kPa (Pa with units = :si)
x1, x2, x3Float64composition of each component, in the order of components
value, unitFloat64, Stringthe measured value and its unit
unc, unc_k, unc_levelFloat64uncertainty as published, its coverage factor and its level of confidence (as a fraction)
unc_k2Float64expanded uncertainty restated at  

An absent number is always NaN, never missing, so every numeric column stays a dense Vector{Float64} and arithmetic and plotting need no special handling. Use isfinite to keep the points that have a value:

julia
count(isfinite, t.unc_k2), length(t.unc_k2)
(64, 64)

Native units or SI ​

By default value, unc, unc_k2 and pressure are reported in the unit of the source, written in the unit column. This is lossless and mirrors the publication. With units = :si, they are converted to the coherent SI unit of the same dimension:

julia
native = table(v)
si = table(v; units = :si)

(native = (native.value[1], native.unit[1]), si = (si.value[1], si.unit[1]))
(native = (4.162188, "kPa"), si = (4162.188, "Pa"))

Temperatures are always kelvin, and compositions are never converted: xkind tells you what they express.

Unitful columns ​

With unitful = true, the columns temperature, pressure, value, unc and unc_k2 hold Unitful quantities, so units travel with the numbers:

julia
tu = table(v; unitful = true)

uconvert.(u"°C", tu.temperature[1:3]), uconvert.(u"mbar", tu.value[1:3])
(Unitful.Quantity{Float64, 𝚯, Unitful.FreeUnits{(K,), 𝚯, Unitful.Affine{-5463//20}}}[29.653999999999996 °C, 29.91900000000004 °C, 29.924000000000035 °C], Unitful.Quantity{Float64, 𝐌 𝐋^-1 𝐓^-2, Unitful.FreeUnits{(mbar,), 𝐌 𝐋^-1 𝐓^-2, nothing}}[41.621880000000004 mbar, 42.142619999999994 mbar, 42.37536 mbar])

Vectors of quantities are fast only when every element has the same type, which means the same unit. That is why unitful = true requires a selection with a single unit and tells you how to fix one that has several:

julia
mixed = points(db; component = "water", exact = true, property = ["Mass density", "Viscosity"],
               temperature = (20u"°C", 30u"°C"))
try
    table(mixed; unitful = true)
catch err
    println(sprint(showerror, err))
end
ArgumentError: unitful = true needs a single unit, but the selection mixes "Pa*s", "kg/m3"; narrow it with `property` first

Narrow the selection by property, or leave unitful off and use the unit column, which handles any mixture of properties.

Tables.jl ​

A DataView is itself a Tables.jl source, and table returns a Tables.jl column table, so anything in the ecosystem accepts them directly:

julia
df = DataFrame(v)
first(df[:, [:components, :property, :temperature, :value, :unit]], 4)
