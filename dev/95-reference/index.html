ThermophysicalDB.ThermophysicalDB — Module
ThermophysicalDB

Download, cache and query experimental thermophysical property data from public databases, starting with the NIST/TRC ThermoML Archive.

ThermophysicalDB.K2_POLICIES — Constant

Coverage factors for converting expanded uncertainties to a common k = 2 basis.

An expanded uncertainty is U = k * u, where u is the standard uncertainty and k the coverage factor. A source that reports U together with a level of confidence p (the probability that the true value lies in y ± U) does not state k; it follows only if a distribution is assumed. For a normal distribution k is the two-sided quantile z, e.g. z = 1.96 for p = 0.95. By convention (GUM) k = 2 is used as the round number for about 95 %. The two readings differ by about 2 %, so both are kept:

  • :nominal: the conventional round k (0.95 -> 2). No distribution is assumed.
  • :normal: the exact normal quantile (0.95 -> 1.95996...).

ThermophysicalDB.MAX_COMPONENTS — Constant

Maximum number of components of a system. The archive never exceeds three.

ThermophysicalDB.NO_ID — Constant

Identifier conventions shared by every table of the schema.

Identifiers are Int32 positions into the owning table. NO_ID (zero) means "absent", so a column of identifiers never needs missing.

DataView(dataset, rows)

A lazy selection of measurements: it stores only the row numbers (rows, positions in dataset.measurements) and never copies values. Refine it with points and turn it into columns with table. ThermophysicalDB.ExperimentTable — Type
ExperimentTable()

One row per studied system in a publication (a ThermoML PureOrMixtureData block): a reference plus up to MAX_COMPONENTS compounds. kinds[i] is the identifier (in the dataset's composition-kind pool) of the variable that expresses the amount of component i, e.g. "Mole fraction" or "Molality, mol/kg".

source
ThermophysicalDB.ExtraTable — Type
ExtraTable()

Sparse key-value store (long format) for fields that have no column in the core schema. Row i says: in the table given by scope[i], row row[i] has the field key[i] with the numeric value number[i] (NaN for text) or the text text[i] (NO_ID for a number). Keys and texts are identifiers into the dataset's extra_keys and extra_texts pools. Core queries never touch this table.

source
ThermophysicalDB.Manifest — Type
Manifest

Record of the archive installed in the local cache, stored as manifest.toml next to it. It is written last, so a manifest on disk always describes a verified, complete archive.

source
ThermophysicalDB.MeasurementTable — Type
MeasurementTable()

One row per measured property value (the "long" format). Numbers are Float64 in the unit the source used (see PropertyTable); NaN marks an absent number.

  • unc: uncertainty exactly as reported, with unc_k (coverage factor) and unc_level (level of confidence as a fraction) when the source gave them. The k = 2 version is derived on demand, so changing the policy never leaves stale data on disk.
  • temperature (K) and pressure (kPa) are the state conditions of the point.
  • composition[i] is the amount of component i, expressed as kinds[i] of its experiment.

PropertyTable()

ThermophysicalDB.ReferenceTable — Type
ReferenceTable()

ThermophysicalDB.Release — Type
Release

One published version of the ThermoML archive.

Fields

  • version: ISO date taken from the archive name, e.g. "2020-09-30".
  • archive_name: file name of the .tgz.
  • archive_url: where the .tgz can be downloaded.
  • sha256_url: where its SHA-256 digest is published.
  • sha256: digest known in advance (built-in releases only), otherwise nothing.
source
ThermophysicalDB.StringPool — Type
StringPool()

Interning table that maps repeated strings (methods, phases, composition kinds, source names) to small integer identifiers. The empty string is always NO_ID and is never stored.

source
ThermophysicalDB.UnitSpec — Type
UnitSpec(native, unitful, si, to_si)

One entry of the closed unit catalog used by the ThermoML archive.

  • native: unit string exactly as written in the property name ("kPa*kg/mol").
  • unitful: the same unit as a string that Unitful.uparse understands.
  • si: the coherent SI unit with the same dimension ("Pa*kg/mol").
  • to_si: factor that converts a value in native into si.

Only multiplicative conversions occur in the archive (all temperatures are kelvin), so no offset is needed.

source
ThermophysicalDB.UpdateStatus — Type
UpdateStatus

Result of check_update.

Fields

  • state: :not_installed, :up_to_date, :update_available or :unknown (the remote could not be queried and nothing newer is known).
  • installed: the local Manifest, or nothing.
  • latest: the most recent Release known.
  • source: :remote if latest came from NIST, :builtin if NIST was unreachable.
  • reason: why NIST could not be queried (empty when source == :remote).

ThermophysicalDB.build_dataset — Method
build_dataset(archive; source = "thermoml", chunk_size = 128, progress = true)
    -> (dataset, report)

Parse every article of a ThermoML .tgz archive into a Dataset. The archive is streamed; articles are parsed in chunks, in parallel on all available threads (start Julia with -t auto), and merged in file order, so the result does not depend on the thread count. Articles that fail to parse are skipped and listed in report.failed.

ThermophysicalDB.coverage_factor — Method
coverage_factor(level; policy = :nominal) -> Float64

Coverage factor k for a two-sided level of confidence given as a fraction in (0, 1) (for example 0.95, not 95). Supported levels are 0.6827, 0.90, 0.95, 0.9545, 0.99 and 0.9973; any other level throws an ArgumentError, because guessing would invent data.

ThermophysicalDB.data_dir — Method
data_dir(; create = false) -> String

Root directory where ThermophysicalDB keeps its data. Resolution order:

  1. the environment variable THERMOPHYSICALDB_DATA_DIR;
  2. the preference stored by set_data_dir!;
  3. the platform default, see default_data_dir.

The directory is only created when create = true.

source
ThermophysicalDB.database — Method
database(; update = :notify, reload = false, rebuild = false, dir = thermoml_dir())
    -> Dataset

The ThermoML database, ready to query with points.

The first call ever downloads the archive from NIST, parses it and saves a binary cache next to it, which takes a few minutes. Later sessions only check whether NIST has a newer archive (update as in ensure_archive: :notify warns, :install upgrades, :never stays offline) and then load the cache, which is much faster than parsing. A changed archive or schema version rebuilds the cache automatically.

Calling database() again in the same session returns the same object immediately; reload = true repeats the update check and the load, rebuild = true also ignores the cache and parses the archive again.

db = database()
points(db; component = "hexane", property = "Thermal conductivity")

ThermophysicalDB.download_file — Method
download_file(url, dest; progress = true, timeout = Inf, attempts = 4) -> String

Download url into dest. Each of up to attempts rounds tries, in order, Julia's Downloads, Downloads with a browser-style User-Agent, and the system curl when it exists; the first that works wins. Between rounds it waits 2, 5 and 10 seconds and says why it is retrying. When everything fails it throws a DownloadError that lists every failure and what the user can do. A partial file is never left at dest.

ThermophysicalDB.ensure_archive — Method
ensure_archive(; update = :notify, dir = thermoml_dir()) -> Manifest

Make sure a verified ThermoML archive is available locally and return its manifest (see archive_path for the file). If nothing is installed, the latest archive is downloaded. Otherwise update decides what happens when NIST has a newer one:

  • :notify (default): keep using the local archive and log a warning;
  • :install: download and switch to the newer archive;
  • :never: do not even contact NIST.

ThermophysicalDB.install_archive! — Method
install_archive!(path; version = nothing, sha256 = nothing, dir = thermoml_dir(),
                 keep_old = false) -> Manifest

Install a ThermoML archive that is already on disk, e.g. one downloaded in a browser from https://data.nist.gov/od/id/mds2-2422. The file is verified against its SHA-256 (taken from sha256, else from path * ".sha256", else from the releases this package knows), copied into the data directory and recorded, exactly like a download. Afterwards database uses it.

version ("2020-09-30") is read from a file name such as ThermoML.v2020-09-30.tgz when not given. A file whose digest does not match is rejected and nothing is installed.

source
ThermophysicalDB.install_release — Method
install_release(release; dir = thermoml_dir(), download = download_file,
                keep_old = false) -> Manifest

Download release into dir, verify its SHA-256 digest and record it in the manifest. The archive is first written to a .part file and only moved into place after the digest matches, and the manifest is written last, so an interrupted or corrupted download never looks like a valid installation. Archives of other versions are deleted afterwards unless keep_old = true.

download(url, dest) can be replaced, e.g. in tests.

ThermophysicalDB.points — Method
points(dataset_or_view; kwargs...) -> DataView

Select experimental points. Every keyword is optional and they combine with AND; calling it on a DataView refines that view, so filters can be chained.

  • component: a name, formula or InChIKey, or a vector of them. With match = :any (default) a system qualifies if it contains any of them, with match = :all if it contains all of them. exact = true requires the system to consist of exactly the listed components (component = "methane", exact = true is pure methane).
  • pure: true for single-component systems, false for mixtures.
  • property: a label such as "Mass density" (any case), a Regex, or a vector.
  • temperature, pressure: (low, high); nothing leaves a side open. Plain numbers are in K and kPa; Unitful quantities are converted, e.g. temperature = (20u"°C", 40u"°C") and pressure = (1u"atm", 2u"atm"). Points without that condition are excluded when the filter is given.
  • doi, author (substring, any case), source (e.g. "thermoml"), year.

A component or property that matches nothing throws an ArgumentError, so a typo is never mistaken for "no data".

ThermophysicalDB.set_data_dir! — Method
set_data_dir!(path) -> String

Persistently set the root data directory through Preferences.jl. The preference lives in the LocalPreferences.toml of the active Julia environment, so it applies only to that environment. ThermophysicalDB.split_property_name — Method
split_property_name(name) -> (label, spec)

Split an archive property name such as "Mass density, kg/m3" into its label and its UnitSpec. The unit is the text after the last ", ", and it is accepted only when it is in the catalog. Otherwise ("Mole fraction", "Refractive index (Na D-line)") the whole name is the label and spec is nothing, meaning dimensionless.

Callers that must detect uncatalogued units can check whether spec === nothing while occursin(", ", label).

ThermophysicalDB.table — Method
table(view; units = :native, policy = :nominal, unitful = false) -> NamedTuple

Materialise a DataView as a NamedTuple of columns (a valid Tables.jl table, so DataFrame(table(v)) works). One row per point, with the columns

source, doi, year, components, xkind, property, method, phase, temperature, pressure, x1, x2, x3, value, unit, unc, unc_k, unc_level, unc_k2.

units = :native keeps the unit of the source (kPa, kJ/mol, ...). units = :si converts value, unc, unc_k2 and pressure (to Pa) and reports the SI unit in unit. unc_k2 is the uncertainty at k = 2 (see coverage_factor for policy); it is NaN where it cannot be derived without inventing data, and a warning counts such rows. Compositions x1..x3 are never converted: xkind tells what they express.

With unitful = true the columns temperature, pressure, value, unc and unc_k2 hold Unitful.Quantity values (temperature in K, pressure in kPa or Pa for units = :si). Every element of a Vector{<:Quantity} shares one concrete type, which keeps broadcasting fast, so the selection must contain a single unit: narrow it with property first, or an ArgumentError lists the units found. Dimensionless properties stay plain numbers. The unit column is kept as text.
