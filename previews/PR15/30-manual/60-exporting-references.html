Exporting the references ​

Every measurement in the database belongs to a published article. This page shows how to export the articles behind a selection, as BibTeX entries and as a summary table. bibtex returns the BibTeX entries of all the articles behind a selection, and write_bibtex writes them to a file:

julia
using ThermophysicalDB

db = database()
v = points(db; component = "water", exact = true, property = "Mass density")

report = write_bibtex("water.bib", v)

A DataView (the result of points) or the whole Dataset can be given. Each article appears once, however many points it contributes.

Where an entry comes from ​

Two sources describe an article, and both are used:

  1. The DOI. The entry is requested from the DOI resolver (with DOI2BibTeX.jl), which returns the publisher's own record, with the journal title abbreviated.

  2. The archive. The ThermoML Archive stores the authors, title, journal, year, volume, pages and DOI of each article.

The two are compared field by field. The DOI entry is the one written. A field that only the archive has is added to it. When both have a field and the values differ (compared without case, accents or punctuation, so 541-612 and 541--612 agree), the entry from the DOI is kept and the disagreement is recorded in the report. An article whose DOI cannot be resolved, or that has none, is written from the archive alone.

julia
report                  # counts: articles, resolved, written from the archive alone
report.conflicts        # (doi, field, resolver, archive) for every disagreement
report.archive_only     # DOIs (or titles) that could not be resolved

Keys ​

The key of an entry has the form that the reference manager gives: the surname of the first author, the year and the first word of the title, all in lower case and without accents, as in chirico2003thermoml or myers1999surfaces. A surname with a particle is written together (da Costa gives dacosta), hyphens and spaces disappear, and The or A count as the first word like any other. When there is no year the key has sd in its place (no date), and anonymous stands for a missing author. If a library you keep in a reference manager generates the same pattern, the keys of an exported .bib agree with those of your library and a text can cite both without renaming anything. When two entries give the same key, both get the suffixes a, b, c, ... in the order of their DOI, so the keys do not depend on the order of the points. The entries for the ThermoML Archive (with the authors and the version of the dataset) and for the standard are always added, so the data are credited wherever the file goes; pass include_source = false to leave them out. They are written once, in the CITATION.cff of the package, together with the entry of the package itself.

The entry of this package (ThermophysicalDB) follows them, after a comment asking you to cite the package if it was useful to your work. It is built from the CITATION.cff of the installed version, so it never drifts from the citation the repository announces: the version is that of the installation, and when the file holds the DOI of the release (Zenodo) the entry carries it. If the file also has a preferred-citation, the article of the package, it becomes a second entry (ThermophysicalDBArticle). The package is credited in the .bib only; no table cites it. Pass include_package = false to leave it out.

The cache and the network ​

The entries delivered by the DOI resolver are kept in the bibtex folder of database_dir, one file per DOI, so each article is requested only once. The requests are made a few at a time.

onlinetruefalse uses only the cache and the archive, with no network at all

A table of the articles ​

A bibliography says which articles were used, not what each one measured. reference_summary condenses a selection into a table with one row per article and property: an article that measured two properties has two rows.

julia
articles = reference_summary(v)                      # K and MPa by default
articles = reference_summary(v; temperature_unit = u"°C", pressure_unit = u"kPa")
ColumnContent
key, doi, year, month, citationthe article, with the key of the BibTeX export and Author et al. (year)
property, unit, system, method, phasewhat was measured, in which system and phase, and how
n_points, n_uncertaintypoints, and how many of them state an uncertainty
T_min, T_max, p_min, p_maxranges of the conditions, in the units you choose
unc_abs, unc_relexpanded uncertainty at  : absolute, in the unit of the property, and relative in percent
purity, purity_min, purity_maxthe purity of the samples, as text (methane 99.95 % mass) and as a range in percent
purity_basis, purity_methodhow the purity is known: supplier, measured or estimated, and the analysis methods the article names
purification, sample_source, supplierthe purification methods, where the samples came from (Commercial source, ...), and the supplier when one is named

The summary is a Tables.jl table (DataFrame(articles) works) and prints as a table in the REPL.

  • Units. temperature_unit and pressure_unit accept any Unitful temperature or pressure unit, including u"°C" and u"bar". The database keeps K and kPa; the conversion is applied to the limits of each range only.

  • Uncertainty. The value of a row is the median over the points that state an uncertainty (statistic = :median, the default, which is not thrown off by an outlier or by a property that passes near zero); statistic = :mean gives the mean. Points without an uncertainty are not counted in it.

  • Methods. A method name longer than method_length characters (24 by default) is replaced by its initials, Vibrating tube method becoming VTM; two different names with the same initials are numbered (VTM, VTM2). The note that explains them is part of the LaTeX and Markdown output.

  • Samples. The purity columns come from what each article says about the samples of its points. Where an article does not describe a sample, the text is empty and the range is NaN, like any other absent value. purity_basis is supplier when the purity is the one stated by the supplier, measured when an analysis (gas chromatography, Karl Fischer titration, ...) is named, and estimated when the compiler of the data estimated it; when the samples of a row differ, the distinct classes are listed. The ThermoML archive has no field for the name of the supplier, so supplier is empty for its data; sample_source holds the closest it says. A purity is a mass, mole or volume fraction as stated, and the text says which; the range mixes them, as the articles do. The full records are in sample_table and purity_step_table.

  • Order. By year, from the oldest to the newest; within a year, by month when the DOI entry has one, otherwise alphabetically by key.

LaTeX, Markdown and CSV ​

julia
write("water.tex", latex_table(articles))
write("water.md", markdown_table(articles))
write("water.csv", csv_table(articles))

latex_table writes a longtable with booktabs rules (load both packages). The first column holds \cite{key} with the keys of the BibTeX export, so the table and the .bib agree; reference = :text writes Author et al. (year) instead. The property and the system columns appear only when they vary within the table. By default the table also shows the purity, its analysis and the purification, when some article states them. Choose the columns, and the number of significant digits, with keywords; the columns are :reference, :property, :system, :method, :phase, :points, :temperature, :pressure, :uncertainty, :uncertainty_abs, :purity, :purity_basis, :purity_method, :purification, :sample_source and :supplier:

julia
latex_table(articles; columns = [:reference, :method, :points, :temperature, :pressure, :uncertainty],
            digits = 5, label = "tab:water")
latex_table(articles; columns = [:reference, :temperature, :pressure, :uncertainty,
                                 :purity, :purity_basis, :purity_method, :purification])

csv_table and the references sheet of an Excel export always hold every column, with the full method names.

write_references writes the BibTeX file and the tables in one call, from the same summary, so they cannot disagree:

julia
write_references("water", v; pressure_unit = u"kPa", statistic = :mean)
# water.bib  water.tex  water.md  water.csv   (choose with formats = (:bib, :tex))

The notice ​

References of data from the ThermoML Archive carry the same notice as the exported points (see Exporting points): the origin of the data, the full citation of the dataset, that the data are modified and not endorsed by NIST/TRC, a reminder to credit the original articles, and the address of the terms.

FileWhere
.biba @comment{...} before the first entry, which BibTeX and biber ignore; it stays even with include_source = false
.tex (latex_table)comment lines starting with %
.md (markdown_table)an HTML comment at the top
.csv (csv_table)the first line, starting with #; read it with header = 2 or comment = "#"

notice = false leaves the notice out of the three table functions, for a table that goes onto a slide; the conditions of use still apply to the data. A selection that holds none of the archive's points (your own data) has no notice. The tutorial Tables for a paper shows all of this with a complete .bib.

Credit

The metadata come from the DOI resolver and from the ThermoML Archive. Check an entry against the article before relying on a volume, a page number or a journal abbreviation in a publication.
