Getting the database ​

ThermophysicalDB.ThermophysicalDB Module
julia
ThermophysicalDB

Download, cache and query experimental thermophysical property data from public databases, starting with the NIST/TRC ThermoML Archive.

source
ThermophysicalDB.database Function
julia
database(; update = :notify, reload = false, rebuild = false, dir = thermoml_dir())
    -> Dataset

The ThermoML database, ready to query with points.

The first call ever downloads the archive from NIST, parses it and saves a binary cache next to it, which takes a few minutes. Later sessions only check whether NIST has a newer archive (update as in ensure_archive: :notify warns, :install upgrades, :never stays offline) and then load the cache, which is much faster than parsing. A changed archive or schema version rebuilds the cache automatically.

Calling database() again in the same session returns the same object immediately; reload = true repeats the update check and the load, rebuild = true also ignores the cache and parses the archive again.

julia
db = database()
points(db; component = "hexane", property = "Thermal conductivity")

ThermophysicalDB.check_update Function
julia
check_update(; dir = thermoml_dir()) -> UpdateStatus

Compare the local archive with the latest one published by NIST. Never throws because of network problems: when NIST cannot be reached the built-in release list is used and source is :builtin. When NIST answers but its record holds no archive link we recognise, source is :unrecognized and a warning is logged, once per session.

An archive republished under the same name counts as an update: when the version is the installed one but the .sha256 published by NIST differs from the digest recorded at installation, the state is :update_available and republished is true.

ensure_archive(; update = :notify, dir = thermoml_dir()) -> Manifest

Make sure a verified ThermoML archive is available locally and return its manifest (see archive_path for the file). If nothing is installed, the latest archive is downloaded. Otherwise update decides what happens when NIST has a newer one:

ThermophysicalDB.install_archive! Function
julia
install_archive!(path; version = nothing, sha256 = nothing, dir = thermoml_dir(),
                 keep_old = false) -> Manifest

Install a ThermoML archive that is already on disk, e.g. one downloaded in a browser from https://data.nist.gov/od/id/mds2-2422. The file is verified against its SHA-256 (taken from sha256, else from path * ".sha256", else from the releases this package knows), copied into the data directory and recorded, exactly like a download. Afterwards database uses it.

version ("2020-09-30") is read from a file name such as ThermoML.v2020-09-30.tgz when not given. A file whose digest does not match is rejected and nothing is installed.

Selecting and extracting points ​

ThermophysicalDB.points Function
julia
points(dataset_or_view; kwargs...) -> DataView

Select experimental points. Every keyword is optional and they combine with AND; calling it on a DataView refines that view, so filters can be chained.

  • component: a name, formula or InChIKey, or a vector of them. Names are matched loosely (case, accents, hyphens and spaces are ignored, so "iso-butane" finds "isobutane"; see find_compounds); a compound id or the result of find_compounds is accepted too. With match = :any (default) a system qualifies if it contains any of them, with match = :all if it contains all of them. exact = true requires the system to consist of exactly the listed components (component = "methane", exact = true is pure methane).

  • pure: true for single-component systems, false for mixtures.

  • property: a label such as "Mass density" (any case), a Regex, or a vector.

  • temperature, pressure: (low, high); nothing leaves a side open. Plain numbers are in K and kPa; Unitful quantities are converted, e.g. temperature = (20u"°C", 40u"°C") and pressure = (1u"atm", 2u"atm"). Points without that condition are excluded when the filter is given.

  • doi, author (substring, any case), source (e.g. "thermoml"), year.

A component or property that matches nothing throws an ArgumentError, so a typo is never mistaken for "no data".

source
ThermophysicalDB.mixture Function
julia
mixture(dataset_or_view, components...; exact = true, kwargs...) -> DataView

Points of the systems made of the given components, in any order: mixture(db, "nitrogen", "isobutane") is the binary nitrogen + isobutane. It is points(db; component = [components...], match = :all, exact = true, kwargs...), so components are matched loosely (see find_compounds) and every other keyword of points (property, temperature, ...) can be added. With exact = false systems that contain further components are included.

When nothing is found, a message tells whether the components do occur together with others, so an empty result can be told apart from a too strict one.

ThermophysicalDB.find_compounds Function
julia
find_compounds(dataset, text; limit = 10) -> CompoundMatches

Find the compounds that text refers to, however it is spelled. Case, accents, hyphens and spaces are ignored ("Iso-Butane" is "isobutane"), "n-hexane" also finds "hexane", and a short list of abbreviations and alternative spellings is understood ("IPA", "sulphur", "propylene"). An InChIKey or a formula ("N2") is matched as written; a formula can be shared by several compounds ("C4H10" is butane and isobutane).

The result lists exact matches first (:exact), then names that contain the text or are contained in it (:contains, so "butane" also lists "isobutane"), then names a few spelling errors away (:similar). points tells how many measurements are in systems that contain each compound, which shows at a glance which spelling is the one with data.

Pass the result as component to points to select every compound it lists, or pick rows with component = result.id[2].

julia
find_compounds(db, "iso-butane")
points(db; component = find_compounds(db, "isobutane"; limit = 1))

ThermophysicalDB.table Function
julia
table(view; units = :native, policy = :nominal, unitful = false) -> NamedTuple

Materialise a DataView as a NamedTuple of columns (a valid Tables.jl table, so DataFrame(table(v)) works). One row per point, with the columns

source, doi, year, components, xkind, property, method, phase, temperature, pressure, x1, x2, x3, value, unit, unc, unc_k, unc_level, unc_k2.

units = :native keeps the unit of the source (kPa, kJ/mol, ...). units = :si converts value, unc, unc_k2 and pressure (to Pa) and reports the SI unit in unit. unc_k2 is the uncertainty at k = 2 (see coverage_factor for policy); it is NaN where it cannot be derived without inventing data, and a warning counts such rows. Compositions x1..x3 are never converted: xkind tells what they express.

With unitful = true the columns temperature, pressure, value, unc and unc_k2 hold Unitful.Quantity values (temperature in K, pressure in kPa or Pa for units = :si). Every element of a Vector{<:Quantity} shares one concrete type, which keeps broadcasting fast, so the selection must contain a single unit: narrow it with property first, or an ArgumentError lists the units found. Dimensionless properties stay plain numbers. The unit column is kept as text.

Exporting points ​

ThermophysicalDB.export_points Function
julia
export_points(directory, view; formats = nothing, reference = :key, units = :native,
              policy = :nominal, details = false, sheets = :system, references = true,
              include_package = true, online = true, cache = true, refresh = false,
              progress = true) -> ExportReport

Write the points of view (a DataView, or a Dataset for all of them) to the directory directory, which is created if it does not exist, with one file per format: for export_points("data/water", v), data/water/water.csv, water.md and so on. formats is a tuple of symbols; the default is (:csv, :md, :tex, :json, :jld2), plus :xlsx when the XLSX package is loaded (using XLSX).

FormatFileContent
:csvname.csvone table; every header carries the unit of its column in brackets
:mdname.mdthe same table as a Markdown table
:texname.texthe same table as a LaTeX longtable with booktabs rules
:jsonname.jsonone record per point, with the origin as its first entry
:jld2name.jld2the columns, units and references as Julia data
:xlsxname.xlsxone sheet per system (sheets = :system, or :single), a references sheet and an origin sheet
:thermomlname.thermoml.jsona subset of the ThermoML schema (see below)

The path is a directory name, not a file name: "data/water.csv" is an error, so a leftover extension never silently creates a directory with a dot in its name. End the path with a slash to keep a dot in the name ("data/water.v2/").

The tables hold points only. The articles are described in the references table, linked through the reference column: reference = :key writes the BibTeX key (the same keys as bibtex; in the .tex it is \cite{key}), :text a written-out citation (Chirico et al. (2003)) and :doi the DOI. With references = true the references are written next to the points: name_references.csv, name_references.md and name_references.tex for each of those formats that was chosen, and name.bib. The .json, .jld2 and .xlsx hold the references table inside the file. The .bib also holds the entry of this package (see bibtex; include_package = false leaves it out).

Columns that are empty for the whole selection are left out. So are the ones that repeat what the references table says or what is the same in every row: the method and the phase of each point, the components when the selection has a single system and the property when it has a single property. details = true writes them all.

Data from the ThermoML Archive carry a notice in every format (the first line of a .csv, a comment in a .md and a .tex, the origin entry of a .json, an origin sheet in a .xlsx, the origin group of a .jld2, and an @comment in the .bib): where the data come from, the citation of the dataset, that they are modified and not endorsed by NIST/TRC, and that the articles must be credited. With references = false and reference = :key a table keeps no way back to the DOIs, and a warning says so.

units = :si converts values, uncertainties and pressure to SI (see table); the ThermoML subset always keeps the units of the archive. The uncertainty columns are unc (as reported) and unc_k2 (at  , see policy in table). online, cache, refresh and progress act as in bibtex.

The ThermoML subset holds, for every article of the selection, its Citation, the Compounds and the PureOrMixtureData with the selected points only, in the structure the archive uses, and so can be read back with the same code. It is a subset: fields the package does not keep (such as the apparatus or the evaluator) are absent. A directory with only formats = (:thermoml,) needs neither references nor network.

Examples

julia
v = points(db; component = "water", exact = true, property = "Mass density")
export_points("data/water", v)                                # csv, md, tex, json, jld2
export_points("data/water", v; formats = (:csv, :thermoml))

References of a selection ​

ThermophysicalDB.bibtex Function
julia
bibtex(view; online = true, cache = true, refresh = false, include_source = true,
       include_package = true, progress = true) -> String

BibTeX entries of every article behind the points of view (a DataView, or a Dataset for all of them), one entry per article.

For each article the entry delivered by the DOI resolver is compared with the metadata stored in the archive. The resolver is used wherever both have a field, a field that only the archive has is added, and the fields on which they disagree are listed by write_bibtex. An article whose DOI cannot be resolved is written from the archive alone.

The key of an entry has the form of the reference manager's: the surname of the first author, the year and the first word of the title, in lower case and without accents, for example chirico2003thermoml. When two entries give the same key, both get the suffixes a, b, c, ... in the order of their DOI.

Keywords

  • online: contact the resolver. With false only the cache and the archive are used.

  • cache: keep the entries delivered by the resolver in database_dir()/bibtex, so each DOI is requested once.

  • refresh: ignore the cache and request every DOI again.

  • include_source: add the entries for the ThermoML Archive and for the ThermoML standard, which credit the origin of the data.

  • include_package: add the entry of this package, read from its CITATION.cff (the version in use, its DOI when the file has one and the article of the package when the file lists it), preceded by a comment asking you to cite it. Nothing in the tables refers to it.

  • package_cff: another file to read it from; by default the CITATION.cff of the package.

  • progress: print the number of DOIs fetched.

Examples

julia
db = database()
v = points(db; component = "water", exact = true, property = "Mass density")
print(bibtex(v))

Detecting outliers ​

ThermophysicalDB.find_outliers Function
julia
find_outliers(view_or_dataset; kwargs...) -> OutlierResult

Look for wrong points in a selection of the database. It works like points: hand it a DataView (or a whole Dataset) and it returns, in an OutlierResult, three views that partition the input: kept, outliers and disputed.

julia
v = points(db; component = "water", property = "Mass density")
kept, outliers, disputed = find_outliers(v)
reasons(result)        # why each excluded point was excluded

Three analyses run in order. Each needs enough neighbouring points to say something; a point without them is reported as not tested, never as validated.

  1. Physical rules (physical = true): conditions no real measurement can break (negative temperature, a fraction above 1, a non-positive density, cp/cv < 1, ...), plus the limits in known_limits. A point that fails is an outlier and is left out of the next analyses.

  2. Trend along one axis (trend = true): points of the same system, property and phase that share the other conditions are put in order along T, P or composition, and a window of window neighbours is fitted with a robust parabola. Points of different sources and methods are compared with each other. The distance of each point to the curve fitted without it, in units of the expected scatter, is its z.

  3. Joint surface (joint = true): when two or more axes vary, a quadratic surface with cross terms is fitted to the neighbors nearest points in all axes at once, which finds points that are consistent along each axis but not together.

The z values of each analysis are pooled and tested with Rosner's generalized extreme studentized deviate test ((Rosner, 1983)), which finds several outliers without one hiding another. A point flagged by the surface analysis alone is disputed; one flagged along an axis is an outlier. Several points of the same publication that all lie on one side of the others are disputed as a systematic offset of the source (source_offset = :outlier makes them outliers).

Keywords

  • physical, trend, joint: switch each analysis on or off.

  • window = 9: points per local parabola (at least 5). min_points = 7: shortest line that is analysed. neighbors = nothing: points per surface window, 4p with p = 6 (two varying axes) or 10 (three) coefficients.

  • consensus_fraction = 0.6: fraction of a window that must agree with the curve. inlier_threshold = 2.5: distance, in units of scatter, beyond which a point is not part of the curve; a point is also never flagged with |z| below it.

  • level = 0.05: probability of flagging anything in a set of points that has no outlier, shared among the tests that run on a subgroup. max_outliers = nothing: most outliers looked for per test, a count or a fraction (default 0.1 of the points). critical = :auto: critical values from Rosner's formula with a correction for small samples with several steps; :rosner is the plain formula. Both are closed formulas, nothing is simulated (see esd_critical_values).

  • transform = :auto: coordinates of the fit; :none, or a NamedTuple with response (:auto, :log, :identity), T (:auto, :inverse, :identity) and P (:auto, :log, :identity).

  • tolerance = (T = 0.1, P = 0.01, x = 1e-3): differences below which two states are the same (K, fraction of the pressure, composition).

  • policy = :nominal: how declared uncertainties are brought to a common basis, as in table.

  • known_limits = nothing: a Dict from property label to (low, high); either side may be nothing. Example: Dict("Mass density" => (0, 2500)).

  • source_offset = :disputed, sign_sigma = 2.0.

  • tile = 3: largest number of neighbouring points that share one surface fit in the joint analysis (1: every point is fitted on its own). screening = 0.7: in the joint analysis every tile is first fitted with a cheap robust fit; the tiles where a point lies beyond screening * inlier_threshold (and the ones around a point beyond inlier_threshold) are fitted again with the more expensive and more robust consensus fit. 0 repeats every tile, which is the slowest and most conservative setting.

  • seed = 1: seed of the deterministic generator that draws the subsets of the consensus fit. The same seed always gives the same result, on any number of threads.

  • max_joint_points = 250_000: largest subgroup given to the joint analysis.

Results do not depend on the number of threads. The estimates assume the points of one subgroup are independent; they are not independent when one publication reports a whole series, which is why a systematic offset gets its own category.

ThermophysicalDB.reasons Function
julia
reasons(result) -> NamedTuple

Why every point that was not kept was excluded, as a Tables.jl table with one row per point and reason (a point can have several). Columns:

  • index: position of the point in the input view; measurement: its row in the dataset.

  • category: :outlier or :disputed, the classification of the point as a whole.

  • code: the analysis that raised this reason: :physical_rule, :trend_1d, :joint_surface or :source_offset.

  • axis: the coordinate along which the trend was followed (:T, :P, :x1, :x2), :joint for the surface in all coordinates, or :none.

  • statistic, critical, rank: the ESD statistic Rᵢ, its critical value λᵢ and the step i at which the point was removed; NaN and 0 where no ESD test was involved.

  • z: standardized deleted residual of the point.

  • reference_value, deviation: what the local fit predicts for the point, in the units of the property, and value - reference_value.

  • detail: the reason in words.

  • the context of the point: source, doi, components, property, phase, method, temperature, pressure, x1, x2, x3, value, unit.

ThermophysicalDB.diagnostics Function
julia
diagnostics(result) -> NamedTuple

The numbers behind the trend analysis, for every point that had one, in long format (one row per point and axis), as a Tables.jl table. They are diagnostics: the classification is decided by z and the ESD test alone.

  • index, measurement, stage (:trend_1d or :joint_surface), axis.

  • z, window (points in the window), consensus (points that agree with the curve), phi (scale factor: 1 when the scatter matches the declared uncertainties, larger when the data are noisier).

  • slope, slope_sd: derivative of the property with respect to the axis, in physical units (property unit per K, per kPa, per unit of composition), and its standard error.

  • curvature, curvature_sd: second derivative with respect to the transformed axis (see transform), and its standard error.

  • influence: how many standard errors the point moves the slope by being in the fit (a DFBETAS-like measure; NaN for points outside the consensus).

  • sign_test: whether the sign of the slope agrees with thermodynamic stability. Along pressure, dρ/dP > 0 and dv/dP < 0 (densities and volumes); along temperature, dP_sat/dT > 0 (vapor pressure), dH/dT > 0 and dS/dT > 0 (molar enthalpy and entropy): :consistent, :violation, :inconclusive (the interval of sign_sigma standard errors includes zero) or :not_applicable.

  • cross, cross_sd: on the :joint rows, the mixed second derivative of the first two varying axes (for example ∂²y/∂T∂P) in transformed units, and its standard error.

  • flagged: whether the ESD test flagged the point along this axis.

  • transform: coordinates in which the fit was made.

ThermophysicalDB.esd Function
julia
esd(z; max_outliers = 0.1, level = 0.05, critical = :auto)

Rosner's generalized extreme studentized deviate test ((Rosner, 1983)) on the values z, assumed to be approximately normal once the outliers are removed. It declares up to max_outliers outliers (a count, or a fraction of length(z)) with a probability of about level of declaring any when there are none. Returns an ESDResult.

critical chooses the critical values, see esd_critical_values. Samples of fewer than three values cannot be tested and throw an ArgumentError; NaN must be removed by the caller.

ThermophysicalDB.esd_critical_values Function
julia
esd_critical_values(n, r, level; method = :auto)

Critical values λ₁, …, λᵣ of the generalized ESD test for n values and at most r outliers, as a vector. They are computed in closed form, so they are exactly reproducible and cost O(r) evaluations of Student's t quantile.

  • method = :rosner: Rosner's formula, rosner_lambda, at the given level.

  • method = :auto (default): the same formula at the level level / (1 + 3 (r - 1) / n). The formula treats the steps as if each were a test of its own at level, while the procedure declares an outlier when ANY step exceeds its value; the correction pays for that. It does nothing for r = 1 (Grubbs' test is exact) and little for r ≪ n.

ThermophysicalDB.Transformation Type
julia
Transformation(log_response, inverse_T, log_P)

The coordinates in which a subgroup is fitted. Many properties are close to straight lines or gentle parabolas only after a change of variable, and a local parabola fitted in the wrong variable leaves systematic residuals that look like outliers:

  • log_response: fit ln y instead of y. Viscosity, vapor pressure, diffusion coefficients and the Henry constants span decades and follow Arrhenius-like laws.

  • inverse_T: use 1/T instead of T. It goes with log_response because ln y ≈ A + B/T for an activated process (B = -E/R for a viscosity).

  • log_P: use ln P instead of P. Automatically it is chosen only for the properties that follow a power law of the pressure in a gas (kinematic viscosity, thermal diffusivity, diffusion coefficient: y ∝ 1/P because they carry a factor 1/ρ), and only in a gas phase. Elsewhere it is not: a liquid density is close to linear in P (the Tait equation is linear in ln(P + B) with B of the order of hundreds of MPa), a gas density is linear in P at low pressure, and a viscosity follows Barus' law ln η ≈ a + αP. Ask for it with transform = (P = :log,) where it fits.

Compositions are never transformed.

Every call must write only to storage that belongs to its own i; the result then does not depend on the number of threads.

ThermophysicalDB.esd_critical_values Method
julia
esd_critical_values(n, r, level; method = :auto)

Critical values λ₁, …, λᵣ of the generalized ESD test for n values and at most r outliers, as a vector. They are computed in closed form, so they are exactly reproducible and cost O(r) evaluations of Student's t quantile.

  • method = :rosner: Rosner's formula, rosner_lambda, at the given level.

  • method = :auto (default): the same formula at the level level / (1 + 3 (r - 1) / n). It does nothing for r = 1 (Grubbs' test is exact) and little for r ≪ n.

ThermophysicalDB.flag_certainty Method
julia
flag_certainty(z) -> Vector{Float64}

Estimated probability that each value of the pool z is a true outlier, 1 - fdr, where fdr is the tail-area false discovery rate of (Efron, 2007): among the k values at least as far from zero as |zᵢ|, about n · 2Φ(-|zᵢ| / σ₀) are expected from a pool without outliers, so the fraction of false discoveries is that over k (at most 1). σ₀ is the scale of the bulk of the pool, estimated from its median absolute value and never taken below 1: a pool whose standardized residuals are wider than they should be (noisier than the model assumes) gets a low confidence however large its extremes look. The estimate is empirical and approximate; it is a measure of how well separated the flags are from the rest, not a guarantee.

ThermophysicalDB.lqs_consensus! Method
julia
lqs_consensus!(ws, q, cutoff)

Least quantile of squares on the window ((Rousseeuw, 1984)): among the surfaces through p points of the window, the one for which the q-th smallest scaled residual |yᵢ - ŷᵢ| / uᵢ is smallest, so that at least q points lie within that distance of it. The subsets are drawn with the generator of ws.rng (deterministic), and the winner is refined by concentration steps: refit by weighted least squares on the q points closest to the current surface, which never makes the fit of those points worse. The mask is left in ws.mask: the points within cutoff times the scale of the winner (the scale is the larger of the quantile over cutoff and the declared uncertainty, as in lqs_parabola).

source
ThermophysicalDB.lqs_parabola Method
julia
lqs_parabola(t, y, u, q) -> Union{Tuple{Vector{Bool},Float64},Nothing}

Consensus of a window with a parabola y ≈ c₀ + c₁ t + c₂ t², by least quantile of squares (Rousseeuw 1984): among the parabolas through three points of the window, the one for which the q-th smallest weighted residual |yᵢ - ŷᵢ| / uᵢ is smallest, so that at least q points lie within that distance of it.

The three-point parabolas are enumerated exhaustively, not drawn at random: the result is deterministic and, unlike a count-based RANSAC with a fixed tolerance, does not need to know the scatter in advance. A window has at most a few tens of points, so C(m, 3) is small. Returns the points within cutoff * max(floor, sₚ / cutoff) of the winner, as a mask, and that scale; nothing when no three points have distinct t.

ThermophysicalDB.process_joint! Method
julia
process_joint!(task, set; threaded = true)

Fit the local quadratic surface of every point of the subgroup and fill the result arrays of task; the module header of surface.jl explains the strategy. In short: the points are grouped in tiles that share a window of neighbors points; all tiles get a cheap robust fit; the tiles with a point beyond screening * inlier_threshold (and the tiles around a point beyond inlier_threshold) are fitted again with the least-quantile-of-squares consensus. Distances are measured in the coordinates scaled to the unit range of the subgroup, so that a kelvin and a mole fraction weigh as much as their spans say.

The result does not depend on the number of threads: every tile writes only the entries of its own points, and the random numbers of a tile depend on its number only.

ThermophysicalDB.robust_refit Method
julia
robust_refit(X, y, u, consensus, known, cutoff) -> Union{WindowFit,Nothing}

refit_window iterated until the inlier set stops changing. The consensus step keeps the best q points, which is a truncated sample, so the scale estimated from it is too small and z would be inflated for every point of an honest data set. After each fit the inliers are recomputed as the points with |z| ≤ cutoff under the scale of that fit, which is corrected for the truncation at cutoff (see truncated_variance); the process settles at a scale that agrees with the data ((Rousseeuw and Leroy, 2003)). At most 12 steps are taken.

Critical value λᵢ of Rosner's generalized ESD test for a sample of n values at significance level, step i = 1, 2, …, n - 2:
