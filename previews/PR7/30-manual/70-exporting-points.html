Exporting points ​

export_points writes the points of a selection to a file that other programs can read. One function serves every format: the extension of the path chooses the writer, so the same selection becomes a spreadsheet, a table for a statistics package or a file for another Julia session by changing the name.

julia
using ThermophysicalDB

db = database()
v = points(db; component = "water", exact = true, property = "Mass density")

export_points("data/water.csv", v)      # one table
export_points("data/water.json", v)     # one record per point
export_points("data/water.jld2", v)     # Julia data
export_points("data/water", v)          # no extension: a directory with all of them
PathFile written
name.csvone table; the unit of every column is in its header
name.xlsxone sheet per system, a references sheet and an origin sheet
name.jsonone record per point
name.thermoml.jsona subset of the ThermoML schema, for the selected points only
name.jld2the columns, the units and the references as Julia data
name.texthe same table as a LaTeX longtable, ready to include in a text
name or name/a directory name holding name.csv, name.xlsx, name.json, name.jld2, name.tex and the references

A DataView or the whole Dataset can be given. An extension that is not in the table is an error, so a typo never silently writes something else.

What a table contains ​

The tables hold points and nothing else. Each row is one measured value with the conditions it was measured at; what describes the article lives in the references table. The two are linked by the reference column, and you choose how it reads:

reference =The cell holdsExample
:key (default)the BibTeX key, the same as in bibtexChirico2003
:textthe citation written outChirico et al. (2003)
:doithe DOI10.1016/S0021-9614(02)00306-7

The columns follow table, with reference in place of source, doi and year. Each header carries its unit in square brackets:

text
reference,components,xkind,property,temperature [K],pressure [kPa],x1 [-],value [kg/m3],unc [kg/m3],unc_level [-],unc_k2 [kg/m3]
Moe1990,water,Mole fraction,Mass density,293.15,101.325,1.0,998.0,0.1,0.95,0.1020…

  • When the selection mixes properties, the value columns read value [see unit] and a unit column says which unit each row has.

  • The composition columns x1, x2 and x3 carry the unit of the composition they express (- for fractions, mol/kg for a molality); xkind says which one it is, and if the selection mixes kinds the header reads x1 [see xkind].

  • A column that is empty for the whole selection is left out, and an empty cell is a missing value: nothing in a .csv or .xlsx, no member in a .json record.

  • units = :si converts values, uncertainties and the pressure to SI, as in table. unc is the uncertainty as the article reported it and unc_k2 is restated at   according to policy.

The references table ​

A .csv has no room for a second table, so with references = true (the default) the references are written next to it: water_references.csv, with one row per article and property as in reference_summary, and water.bib. The keys in the reference column are the keys of that file. The other formats carry the references themselves: the references sheet of an .xlsx, the references entry of a .json and the references group of a .jld2. Pass references = false to write the points only.

The BibTeX entries are fetched from the DOI resolver the first time, as in bibtex, and cached; online = false uses only the cache and the archive, so the export works offline. online, cache, refresh and progress act as there.

A directory ​

A path without an extension, or ending with a slash, names a directory:

julia
export_points("data/Fluid", v)
# data/Fluid/Fluid.csv
# data/Fluid/Fluid.xlsx
# data/Fluid/Fluid.json
# data/Fluid/Fluid.jld2
# data/Fluid/Fluid.tex
# data/Fluid/Fluid_references.csv
# data/Fluid/Fluid_references.tex
# data/Fluid/Fluid.bib

All the files are built from the same selection and the same bibliography, so they agree: the same columns, the same units, the same keys. formats chooses the files, for example formats = (:csv, :thermoml). :xlsx is skipped with a warning when the XLSX package is not loaded, unless you ask for it in formats, which is then an error.

The returned ThermophysicalDB.ExportReport lists the files written, the number of points and articles, and the formats skipped.

LaTeX ​

name.tex is the points table as a longtable with booktabs rules (load longtable and booktabs), with the same columns and headers as the .csv. With reference = :key the reference column holds \\cite{Chirico2003}, which resolves against the name.bib written with it; reference = :text writes the citation out instead. name_references.tex is the table of the articles, one row per article and property with the ranges of temperature and pressure and the uncertainty, as latex_table writes it, citing the same keys.

Exporting a directory therefore gives, in one call, the raw points in four formats, the summary of what each article covers, and the bibliography: the data to process and the tables and references to include in a text.

Where the data come from ​

When some of the points come from the ThermoML Archive, every file carries a note saying so: the origin, the DOI of the dataset, the version of the archive on this computer, the date of the export, and that the data are modified (reformatted, possibly converted) and were not evaluated by NIST/TRC. See About the data for what to cite. Points that come from elsewhere, such as your own data, carry no note. The note sits where each format can hold it without disturbing the table:

FormatWhere
.csvthe first line, starting with #, before the headers
.texthe first line, a % comment
.xlsxa separate sheet called origin
.jsonthe first entry of the top-level object, origin
.jld2the origin group

To read a .csv skip that line:

julia
using CSV, DataFrames
df = CSV.read("data/water.csv", DataFrame; comment = "#")

Excel ​

Writing .xlsx files uses XLSX.jl, which is loaded on demand: install it once and load it before exporting.

julia
using XLSX
export_points("data/water.xlsx", v)

By default each system gets its own sheet, named after its components and shortened to the 31 characters Excel allows (water, carbon dioxide + methane); a sheet holds up to 1,048,575 points. sheets = :single puts all the points in one sheet called points. Within a sheet, columns that are empty for that system are left out, so a pure fluid has no x2.

JSON ​

The default .json has one record per point, so each point can be read on its own:

json
{
  "origin": { "data_origin": "NIST/TRC ThermoML Archive", "...": "..." },
  "metadata": { "format": "ThermophysicalDB points", "version": 1, "points": 2, "...": "..." },
  "units": { "temperature": "K", "pressure": "kPa", "value": "kg/m3", "...": "..." },
  "points": [
    {"reference": "Moe1990", "components": "water", "property": "Mass density", "temperature": 293.15, "pressure": 101.325, "x": [1.0], "value": 998.0, "unit": "kg/m3", "unc": 0.1, "unc_k2": 0.102},
    {"...": "..."}
  ],
  "references": { "temperature_unit": "K", "pressure_unit": "MPa", "rows": [ {"key": "Moe1990", "...": "..."} ] }
}

The composition of a point is the array x, with one entry per component in the order of components. Values that are not finite are not written.

In the ThermoML format ​

json_layout = :thermoml, or a path ending with .thermoml.json, writes the selected points in the structure of the archive's own files instead: one object per article with its Citation, its Compounds and the PureOrMixtureData that hold only the selected points. It is a subset, so what the package does not keep is absent, and the units are those of the archive whatever units says. Because the structure is the one the package reads, such a file can be read back with the same parser.

julia
export_points("data/water.thermoml.json", v)

This layout needs neither the references nor the network. Compounds are numbered within each article, as in the archive, and every point is one row of NumValues. Properties whose name the archive writes with a presentation (a ratio or a difference to a reference state) keep that qualifier in ePropName. A composition without a known kind cannot be typed in ThermoML and is not written.

Julia ​

A .jld2 holds each column of the table as points/<name>, the units as units/<name>, the headers as metadata/headers, the references as references/<column> and the origin note as origin/<entry>. Values are plain numbers; the units are text.

julia
using JLD2
jldopen("data/water.jld2") do file
    T = file["points/temperature"]
    ρ = file["points/value"]
    file["units/value"]       # "kg/m3"
end

Choosing a format ​

If you want toUse
open the data in a spreadsheet, with one sheet per system.xlsx
load them in R, Python, Julia or Matlab.csv (a plain table) or .json
keep every number exactly and reload it quickly in Julia.jld2
hand the data to something that reads ThermoML.thermoml.json
give a colleague everythingthe directory

Numbers are written with the shortest text that reads back exactly the same Float64, in .csv and .json as well.
